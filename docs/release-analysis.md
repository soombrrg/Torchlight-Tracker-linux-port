# Разбор оригинального релиза и перенос на Linux

Дата: 2026-10-24. Исследован предоставленный пользователем релиз `TLI-tracker-translated-v1.3.0`. Изменений в дистрибутив не внесено.

После согласования реализован отдельный Linux-порт: [запуск и проверенные ограничения](../linux/README.md). Ниже сохранены результаты первоначального анализа оригинала, включая ограничения именно того этапа.

## Результат

Переписывание с нуля не требуется для первого варианта Linux-порта. В оригинале есть переносимый сборщик логов, Electron IPC и веб-интерфейс. Windows-привязки находятся преимущественно в автопоиске игры, shell bridge, обновляторе и параметрах поставки.

Это вывод о возможности переноса, а не подтверждение полной работоспособности: оригинальный сборщик проверен на Linux, но GUI, сетевой интерфейс и расчёты на реальном забеге ещё не проверены.

## Идентичность артефакта

- Активный архив: `TLI-tracker-translated-v1.3.0/resources/app.asar`, 8 987 028 байт, 399 файлов.
- SHA-256: `5b908d0f3c0c6043ec9f0d781fdfbc66feb135a16b345e63a5ac61a8f5ef370c`.
- Активный entry point из корневого `package.json`: `build/obf-app/main.js`.
- Пакет приложения сообщает версию `1.0.5`; сохранённый локальный UI-бандл — `1.0.5.15`. Версия перевода релиза — `v1.3.0`. Это разные версии разных частей приложения.
- Корневые `main.js` и `tor/main.js` — дополнительные копии, не активные entry points. Их нельзя выдавать за исполняемый код релиза.
- `.node`-модулей в архиве не найдено. Runtime dependencies пакета: `iconv-lite`, `sudo-prompt`, `ws`.
- `app.asar.backup` также проверен: 69 файлов, недостающих web worker/vendor/HTML/CSS в нём нет. Принадлежность резервного архива конкретной версии не установлена.

## Фактический путь данных

1. `build/obf-app/main.js` создаёт Electron BrowserWindow с `preload.js`.
2. Production `loadURL` открывает `https://etor-beta.710421059.xyz/?t=...` (строка 87 активного main).
3. `preload.js` публикует `window.electronAPI`. `startTorLog(path)` вызывает IPC `start-tor-log`.
4. Обработчик `main.js:734` передаёт путь в `tor.mainWatch(logPath, routeLogMessage)`.
5. Активный `build/obf-app/tor/main.js` использует только `fs`, `fs.promises`, `readline`: `stat`, `fs.watch`, чтение UTF-8 порциями до 512 KiB, проверка изменений каждые 250 ms.
6. Backend передаёт строки renderer через IPC и/или WebSocket. Игровые структуры и результаты вычисляет frontend с worker.

Драйвер, перехват памяти игры или платформенная DLL для чтения лога в этом пути не обнаружены. Наличие `sudo-prompt` в dependencies само по себе не означает его использование активным backend.

## Что можно сохранить

- Electron preload и существующий контракт `electronAPI`.
- Оригинальные маршруты UI: главная страница, история, предметы, аналитика, рейтинги, цены, overlay.
- Оригинальные расчёты инвентаря и лута. В локальном UI-бандле `processLootItems` использует разницу нового и предыдущего количества, а не весь размер стека.
- Переводы и механизм их внедрения. В активном main переводы читаются из `userData`/bundled files, независимо от Windows AppData.
- Таблицу предметов `Rt-data.json` (1 811 записей); соответствие текущему сезону отдельно не проверялось.

Оговорка: версия удалённого UI может отличаться от сохранённого бандла. Совместимость текущего сайта и IPC ещё требует запуска.

## Конкретные Windows-привязки

| Место | Текущее поведение | Необходимое изменение для Linux |
| --- | --- | --- |
| Локальный `index-BM0zvaJG.js`, UTF-8 offset 1 298 583 | `chcp 437`, `tasklist`, PowerShell `Get-Process.Path`; путь строится через обратные слеши | Поиск Steam log path вне Windows discovery; использование существующего ручного пути или восстановление активного сервиса через `getTorStatus` |
| Активный `main.js:941` | `exec(command)` и декодирование stdout/stderr как GBK/UTF-16LE | UTF-8 и платформенные операции с явным контрактом; Windows-команды не исполнять на Linux |
| Активный `main.js:727`, `updater.js` | Автопроверка обновлений; установка через Windows tar/PowerShell/CIM/robocopy | Исключить Windows installer из Linux-пути; сохранять адаптированную оболочку при обновлениях |
| Активный `main.js:3` | Принудительные `LANG`/`LC_ALL=zh_CN.UTF-8` | Сохранить локаль пользователя |
| `build/obf-app/package.json:7` | Windows `chcp` в start script | Нативный Linux launcher |
| Там же, строка 57 | Windows `requireAdministrator` | Не переносить требование администратора в Linux-запуск |

UI не блокирует Linux проверкой ОС: desktop-ветка выбирается при отсутствии AndroidBridge. В UI имеется поле ручного пути лога (`BackgroundServiceStatus`, offset 1 034 692), изменение пути запускает `startLogging` после debounce 800 ms.

## Зависимость от сайта автора

Оригинальный production entry point загружает интерфейс с сайта автора. Локальный `index-BM0zvaJG.js` — неполный офлайн-комплект:

- отсутствует `logProcessor-CghJStcI.js`, который обрабатывает строки лога;
- отсутствуют 21 статический vendor import, HTML/CSS и дополнительные web assets;
- базовый URL API в сохранённом бандле: `https://etor-beta.710421059.xyz/etor-api`.

Следовательно, перенос существующего online-приложения и создание полностью автономной версии — разные объёмы работы. Для первого варианта не требуется воссоздавать отсутствующий worker; для второго потребуется получить его и остальные ресурсы либо отдельно восстановить их поведение.

Из этой среды сайт получить не удалось. Это ограничение проверки, а не доказательство недоступности сайта у пользователя.

## Проверка оригинального сборщика на Linux

[Воспроизводимый probe](probes/original-log-reader.cjs) загружает неизменённый активный `tor/main.js` из REA-распаковки. Проверка использует только временные файлы; файлы игры не изменяются, Electron GUI/удалённый renderer не запускаются.

Прогон выполнен под Node 26.12.0 и под Node 24.21.0 установленного Electron 43.7.11 (`ELECTRON_RUN_AS_NODE=1`). [Сохранённые результаты второго прогона](evidence/original-log-reader.json).

| Сценарий | Наблюдение |
| --- | --- |
| Дописывание строки | Новая строка получена, историческая пропущена, кириллица и китайские символы сохранены |
| Строка записана двумя частями с паузой | Callback получает две отдельные строки вместо одной; это дефект исходного reader |
| Усечение файла с сохранением inode | Offset остаётся 74 при размере файла 6; чтение новых данных не восстановлено |
| Замена файла при ротации | Первая уже записанная строка нового файла пропущена; последующая дописанная строка получена |
| Несуществующий файл | Сборщик возвращает `isRunning=false` |

Дополнительный статический дефект: `main.js:744` не ожидает `mainWatch`, после чего сразу задаёт `isLoggingActive=true`. При ошибке пути статус оболочки может противоречить статусу reader. Этот обработчик runtime probe не исполнял.

Наличие системного `electron43` подтверждено: 43.7.11. Обычный вызов `electron43 --version` в sandbox завершился ошибкой Chromium sandbox; Node-режим работает. Это не проверка запуска окна на пользовательском рабочем столе и не доказательство несовместимости с хостом.

## Предлагаемый объём переноса — ещё не согласован

1. Создать Linux-копию активного приложения, сохранив исходный дистрибутив и происхождение файлов.
2. Сохранить production UI автора, переводы, расчёты и IPC. Не заменять их новой реализацией.
3. Добавить Linux launcher и обнаружение лога через стандартные Steam libraries с явным переопределением пути. На этой машине путь уже известен.
4. Связать обнаруженный путь с существующим сервисом логов, исключить Windows discovery и Windows installer из Linux-запуска.
5. Исправить границы строк, усечение/ротацию и согласованность статуса reader. Проверить это сценариями, воспроизведёнными выше.
6. Проверить окно, подключение к реальному remote renderer, сортировку инвентаря и один контрольный забег. Overlay и click-through проверяются отдельно в Hyprland.

До изменения приложения требуется согласовать перенос оригинала с существующей зависимостью от сайта либо полностью автономную версию. ADR о выборе архитектуры пока не создаётся: решение не принято.
